# Jornada de nueve horas

Cinco casos obligatorios. Ocho horas de trabajo y una de descansos; se añade una hora al plan anterior para desarrollar el endpoint sin eliminar alcance. Para principiantes, el quinto caso puede requerir hasta 90 minutos: pilotar la carga y reconocer progreso parcial.

| Horario | Actividad |
|---|---|
| 08:30–09:00 | Preparación y lectura |
| 09:00–09:30 | Ciudades |
| 09:30–10:30 | Historial SQL |
| 10:30–10:45 | Descanso |
| 10:45–12:30 | Directorio administrativo |
| 12:30–13:15 | Almuerzo |
| 13:15–15:00 | Mantenimiento de notificaciones |
| 15:00–16:00 | Endpoint completo de actividades |
| 16:00–16:45 | Pruebas propias y documentación |
| 16:45–17:30 | Demostración y modificación breve |

No se requiere frontend ni acceso a servicios de Apptiva. El cambio breve de la defensa se anuncia desde el inicio y se concreta al comenzar ese bloque. No hay casos opcionales adicionales.

| Bloque | Puntos |
|---|---:|
| Historial SQL | 15 |
| Ciudades | 10 |
| Directorio | 20 |
| Notificaciones | 20 |
| Endpoint de actividades | 15 |
| Pruebas propias y documentación | 10 |
| Demostración y cambio breve | 10 |

Se combina comportamiento HTTP con revisión de código. Las cinco pruebas propias mínimas deben ampliar cobertura y explicar el fallo que detectarían. Se reconoce avance parcial y limitaciones documentadas.
